# :material-web: HTTP Headers

All HTTP calls in DENA include a set of standard and custom headers that provide context, security and traceability.

---

## Request HTTP Headers

| Header | Description | Example |
|---|---|---|
| `Authorization` | JWT token for authentication | `Authorization: Bearer {token}` |
| `If-Modified-Since` | Cache date in [RFC 7231](https://datatracker.ietf.org/doc/html/rfc7231) format | |
| `User-Agent` | Data of the client (browser, app, library) that originates the request. See [UserAgent](./modelo/user-agent.md) | |
| `Content-Type` | Content type of the message (usually `application/json`) | `Content-Type: application/json` |
| `Content-Digest` | SHA-256 digest computed over the whole message | `Content-Digest: sha-256=<digest-value>` |
| `X-DENA-Data-Digest` | SHA-256 digest computed over the data part (body) of the message | `X-DENA-Data-Digest: sha-256=<digest-value>` |
| `X-DENA-This-TimeStamp` | Instant (EPOCH) at which the request was started in the originating component | `1670374400` |
| `X-DENA-Origin-TimeStamp` | Instant (EPOCH) at which the flow was started in the initial component (e.g. mobile app). Kept unaltered across components | `1670374400` |
| `X-DENA-Message-Correlation-Id` | UID generated by the component that started the flow. Kept unaltered across components | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |

---

## Response HTTP Headers

| Header | Description | Example |
|---|---|---|
| `Content-Type` | Content type of the response | `Content-Type: application/json` |
| `Content-Digest` | SHA-256 digest of the response body | `Content-Digest: sha-256=<digest-value>` |
| `X-DENA-Message-Correlation-Id` | Correlation UID (echo of the request) | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |
| `X-DENA-This-TimeStamp` | Instant (EPOCH) at which the response was generated | `1670374500` |

---

## Security digest

The `Content-Digest` and `X-DENA-Data-Digest` headers serve to guarantee the **integrity** of the message:

- `Content-Digest`: SHA-256 hash of the **whole** HTTP message (headers + body)
- `X-DENA-Data-Digest`: SHA-256 hash of only the **body** (data)

This allows the receiver to verify that the message has not been altered in transit.

!!! tip "Correlation and traceability"
    The `X-DENA-Message-Correlation-Id` header allows associating all calls derived from an original request, easing debugging in distributed systems.
