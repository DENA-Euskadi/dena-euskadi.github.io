# :material-arrow-right-bold: Your System Calls DENA

> **Version:** `v{{ dena.version }}` · **Date:** {{ dena.date }}

When your administration makes a call to DENA (sending Metadata-Sync, querying Person-Sync Pull, etc.), it must include authentication and security headers.

---

## Authentication flow

``` mermaid
sequenceDiagram
    participant Admin as Your System
    participant IDP as Keycloak DENA
    participant DENA as CORE DENA

    Admin->>IDP: POST /token (client_credentials)
    IDP-->>Admin: access_token (JWT, 5 min)
    Admin->>DENA: POST /api/... + Bearer token + Security Headers
    DENA-->>Admin: 200 OK
```

---

## 1. Obtain the OAuth2 token

Your system obtains a JWT token from the DENA Identity Provider using the `client_credentials` flow.

### Endpoint

```
POST /realms/DenaAuthAdmins/protocol/openid-connect/token
Content-Type: application/x-www-form-urlencoded
```

### Parameters

| Field | Type | Required | Description |
|---|---|:---:|---|
| `grant_type` | `String` | :material-check: | `client_credentials` |
| `client_id` | `String` | :material-check: | Client ID provisioned by DENA |
| `client_secret` | `String` | :material-check: | Client secret provisioned by DENA |

### curl example

```bash
curl -X POST \
  https://api-batera.pre.dena.eus/auth/realms/DenaAuthAdmins/protocol/openid-connect/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&client_id=<your-client-id>&client_secret=<your-client-secret>"
```

### Successful response (HTTP 200)

```json
{
    "access_token": "eyJhbGciOiJSUzI1NiIs...",
    "expires_in": 300,
    "refresh_expires_in": 0,
    "token_type": "Bearer",
    "not-before-policy": 0,
    "scope": "email profile"
}
```

| Field | Description |
|---|---|
| `access_token` | JWT token to include in the `Authorization: Bearer <token>` header |
| `expires_in` | Seconds until expiration (typically 300 = 5 min) |
| `token_type` | Always `Bearer` |

### Error response (HTTP 4xx)

```json
{
    "error": "invalid_client",
    "error_description": "Invalid client or Invalid client credentials"
}
```

| Error | Cause |
|---|---|
| `invalid_client` | Incorrect `client_id` or `client_secret` |
| `unauthorized_client` | The client does not have permission for `client_credentials` |
| `invalid_grant` | Invalid `grant_type` |

### Token renewal

!!! warning "The token expires in 5 minutes"
    - Cache the token while it is valid
    - Renew it with a **leeway** of ~60 seconds before expiration
    - Do not request a new token for every request

## 2. Security headers

In addition to the token, each call to DENA must include security headers that guarantee the integrity and traceability of the message.

### Required headers

| Header | Description | Example |
|---|---|---|
| `Authorization` | JWT token obtained in the previous step | `Bearer eyJhbGciOiJSUzI1NiIs...` |
| `Content-Type` | Content type | `application/json` |
| `X-DENA-Message-Correlation-Id` | Unique UUID generated by your system for this request. It is maintained throughout the flow for traceability | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |
| `X-DENA-This-TimeStamp` | EPOCH instant (milliseconds) at which your system initiates the request | `1724500500000` |
| `X-DENA-Data-Digest` | SHA-256 hash of the message body (see generation below) | `sha-256=2251f5ac60e4...` |

### Optional headers

| Header | Description | Example |
|---|---|---|
| `Content-Digest` | SHA-256 hash of the complete message (headers + body) | `sha-256=...` |
| `X-DENA-Origin-TimeStamp` | EPOCH instant of the start of the flow in the original component. It is preserved unchanged between components | `1724500500000` |
| `User-Agent` | Identification of your system. Recommended format: `AdminX/<ver> <module>/<ver> (support@admin.eus)` | `MyAdmin/1.0 srmd-sender/1.0 (support@myadmin.eus)` |

### Security field generation

#### X-DENA-Message-Correlation-Id

Generate a random UUID v4 for each request. This ID is maintained throughout the processing in DENA and appears in the logs to facilitate debugging.

```java
String correlationId = UUID.randomUUID().toString();
// Result: "db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb"
```

#### X-DENA-This-TimeStamp

Current instant in milliseconds since EPOCH (1970-01-01T00:00:00Z):

```java
long timestamp = System.currentTimeMillis();
// Result: 1724500500000
```

#### X-DENA-Data-Digest

SHA-256 hash of the request body, encoded in hexadecimal:

```java
import java.security.MessageDigest;
import java.nio.charset.StandardCharsets;

public static String computeDataDigest(String body) {
    MessageDigest digest = MessageDigest.getInstance("SHA-256");
    byte[] hash = digest.digest(body.getBytes(StandardCharsets.UTF_8));
    
    // Convert to hexadecimal
    StringBuilder hex = new StringBuilder();
    for (byte b : hash) {
        hex.append(String.format("%02x", b));
    }
    return "sha-256=" + hex.toString();
}
```

```python
import hashlib

def compute_data_digest(body: str) -> str:
    hash_value = hashlib.sha256(body.encode('utf-8')).hexdigest()
    return f"sha-256={hash_value}"
```

!!! warning "Compute the digest on the exact body"
    The hash must be computed on the exact body that is sent over the network (after JSON serialization). If a proxy or middleware modifies the body after computation, DENA will reject the request.

## 3. Complete call example

Complete request to DENA with all headers:

```bash
# 1. Generate security values
CORRELATION_ID=$(uuidgen | tr '[:upper:]' '[:lower:]')
TIMESTAMP=$(date +%s%3N)
BODY='[{"admin":{"id":"MI-ADMIN"},"aboutPerson":{"id":"12345678A"},"someDataWasUpdatedAt":"2026-08-24T10:30:00.000Z","ofType":{"id":"RECORDS"},"fromDataOrigin":"DEFAULT"}]'
DATA_DIGEST="sha-256=$(echo -n "$BODY" | shasum -a 256 | cut -d' ' -f1)"

# 2. Send with all headers
curl -X POST "https://api-batera.pre.dena.eus/srmd/" \
  -H "Authorization: Bearer ${TOKEN}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -H "X-DENA-Message-Correlation-Id: ${CORRELATION_ID}" \
  -H "X-DENA-This-TimeStamp: ${TIMESTAMP}" \
  -H "X-DENA-Data-Digest: ${DATA_DIGEST}" \
  -H "User-Agent: MyAdmin/1.0 srmd-sender/1.0 (support@myadmin.eus)" \
  -d "${BODY}"
```
