# :material-web: HTTP Headers

All HTTP calls in DENA include a set of standard and custom headers that provide context, security and traceability.

---

## Request HTTP Headers

| Header | Description | Example |
|---|---|---|
| `Authorization` | JWT token for authentication (standard HTTP header; not handled by the DENA traffic-flow) | `Authorization: Bearer {token}` |
| `User-Agent` | Data of the client (browser, app, library) that originates the request. See [UserAgent](./modelo/user-agent.md) | |
| `Content-Type` | Content type of the message (usually `application/json`) | `Content-Type: application/json` |
| `Content-Digest` | SHA-256 digest computed **only over the body** of the message, Base64-encoded | `Content-Digest: SHA-256=:<base64>:` |
| `X-DENA-Data-Digest` | SHA-256 digest computed over the concatenation `X-DENA-This-TimeStamp + X-DENA-Message-Correlation-Id + body`, Base64-encoded | `X-DENA-Data-Digest: SHA-256=:<base64>:` |
| `X-DENA-This-TimeStamp` | Instant (EPOCH in milliseconds) at which the request was started in the originating component | `1670374400000` |
| `X-DENA-Origin-TimeStamp` | Instant (EPOCH in milliseconds) at which the flow was started in the initial component (e.g. mobile app). Kept unaltered across components | `1670374400000` |
| `X-DENA-Message-Correlation-Id` | UID generated by the component that started the flow. Kept unaltered across components | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |

!!! warning "Mandatory traffic-flow headers"

    In interoperability calls protected by the *traffic-flow*, DENA **requires** the headers `X-DENA-This-TimeStamp`, `X-DENA-Origin-TimeStamp`, `X-DENA-Message-Correlation-Id` and `X-DENA-Data-Digest`. If any is missing, the request is rejected with **HTTP 400**. If `X-DENA-Data-Digest` or `Content-Digest` are missing or do not match the received body, it is rejected with **HTTP 401**.

---

## Response HTTP Headers

| Header | Description | Example |
|---|---|---|
| `Content-Type` | Content type of the response | `Content-Type: application/json` |
| `Content-Digest` | SHA-256 digest of the response body (Base64) | `Content-Digest: SHA-256=:<base64>:` |
| `X-DENA-Message-Correlation-Id` | Correlation UID (echo of the request) | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |
| `X-DENA-This-TimeStamp` | Instant (EPOCH in milliseconds) at which the response was generated | `1670374500000` |

---

## Security digest

The `X-DENA-Data-Digest` and `Content-Digest` headers serve to guarantee the **integrity** of the message. Both use **SHA-256** and the resulting hash is **Base64**-encoded:

- `X-DENA-Data-Digest`: SHA-256 hash of the concatenation `X-DENA-This-TimeStamp + X-DENA-Message-Correlation-Id + body`. It binds the body to its timestamp and correlation id.
- `Content-Digest`: SHA-256 hash of **only the body** (the data). It does NOT include the headers.

Value format in both headers: `SHA-256=:<base64-hash>:` (algorithm name, `=:` delimiter, Base64 hash and closing `:`).

The receiver (inbound *traffic-flow* filter) recomputes both digests over the received body and compares them; if they do not match, it rejects the request with **HTTP 401**.

This allows the receiver to verify that the message has not been altered in transit.

!!! tip "Correlation and traceability"
    The `X-DENA-Message-Correlation-Id` header allows associating all calls derived from an original request, easing debugging in distributed systems.
