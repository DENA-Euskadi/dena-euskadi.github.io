# :material-web: HTTP Headers

All HTTP calls in DENA include a set of standard and custom headers that provide context, security and traceability.

---

## Request HTTP Headers

| Header | Description | Example |
|---|---|---|
| `Authorization` | JWT token for authentication | `Authorization: Bearer {token}` |
| `If-Modified-Since` | Cache date in [RFC 7231](https://datatracker.ietf.org/doc/html/rfc7231) format | |
| `User-Agent` | Client data (browser, app, library) originating the request. See [UserAgent](./modelo/user-agent.md) | |
| `Content-Type` | Message content type (usually `application/json`) | `Content-Type: application/json` |
| `Content-Digest` | SHA-256 digest computed over the entire message | `Content-Digest: sha-256=<digest-value>` |
| `X-DENA-Data-Digest` | SHA-256 digest computed over the data (body) part of the message | `X-DENA-Data-Digest: sha-256=<digest-value>` |
| `X-DENA-This-TimeStamp` | EPOCH instant when the request started in the originating component | `1670374400` |
| `X-DENA-Origin-TimeStamp` | EPOCH instant when the flow started in the initial component (e.g. mobile app). Preserved unchanged across components | `1670374400` |
| `X-DENA-Message-Correlation-ID` | UID generated by the component that started the flow. Preserved unchanged across components | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |
| `X-DENA-App-Version` | Client application version | `X-DENA-App-Version: 1.3.4` |
| `X-DENA-OS-Version` | Operating system version | `X-DENA-OS-Version: Android 14` |
| `X-DENA-Device-Model` | Device model | `X-DENA-Device-Model: Pixel 6 Pro` |

---

## Response HTTP Headers

| Header | Description | Example |
|---|---|---|
| `Content-Type` | Response content type | `Content-Type: application/json` |
| `Content-Digest` | SHA-256 digest of the response body | `Content-Digest: sha-256=<digest-value>` |
| `X-DENA-Message-Correlation-ID` | Correlation UID (echoed from request) | `db761b72-1634-4fb0-b7f1-3c1ebbdbb1eb` |
| `X-DENA-This-TimeStamp` | EPOCH instant when the response was generated | `1670374500` |

## API Versioning

DENA uses a **custom HTTP Header** for API versioning:

```
X-DENA-API-VERSION: 1.0
```

!!! info "Versioning options considered"

    | Option | Example |
    |---|---|
    | Version in URL | `/api/v1.0/files` |
    | Custom HTTP Header (chosen) | `X-DENA-API-VERSION: 1.0` |
    | Standard Accept Header | `Accept: application/json;version=1.0` |

---

## Security digests

The `Content-Digest` and `X-DENA-Data-Digest` headers guarantee the **integrity** of the message:

- `Content-Digest`: SHA-256 hash of the **entire HTTP message** (headers + body)
- `X-DENA-Data-Digest`: SHA-256 hash of the **body only** (data)

This allows the recipient to verify the message has not been tampered with in transit.

!!! tip "Correlation and traceability"
    The `X-DENA-Message-Correlation-ID` header allows associating all calls derived from an original request, making debugging easier in distributed systems.
